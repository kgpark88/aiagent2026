# 02. 아키텍처와 오퍼레이션

## 3계층 아키텍처

- **Raw Sources** — 큐레이션한 원본(기사·논문·이미지·데이터). **불변**. LLM은 읽기만 하고 수정하지 않는다. 진실의 원천.
- **Wiki** — LLM이 생성한 마크다운 디렉토리(요약·엔티티·개념·비교·overview·synthesis). LLM이 전적으로 소유한다. 사람은 읽고, LLM이 쓴다.
- **Schema** — 위키 구조·규칙·워크플로우를 적은 문서(Claude Code의 CLAUDE.md, Codex의 AGENTS.md). LLM을 "일반 챗봇"이 아니라 "규율 있는 위키 관리자"로 만드는 핵심 설정. 사람과 LLM이 함께 진화시킨다.

## 3대 오퍼레이션

- **Ingest(수집)** — 새 소스를 넣고 처리 지시. LLM이 소스를 읽고 → 핵심을 논의하고 → 요약 페이지 작성 → index 갱신 → 관련 엔티티·개념 페이지 갱신 → log에 기록. 한 소스가 10~15개 페이지를 건드릴 수 있다.
- **Query(질의)** — 위키에 질문. 관련 페이지를 찾아 읽고 인용과 함께 종합. **좋은 답은 다시 위키에 페이지로 저장**할 수 있다(탐색도 복리로 쌓인다).
- **Lint(점검)** — 주기적 건강 검진. 모순, 낡은 주장, 고립 페이지(inbound 링크 없음), 페이지가 없는 중요 개념, 누락된 상호 참조, 웹 검색으로 메울 데이터 공백을 찾는다.

## 색인과 기록

- **index.md** — 콘텐츠 카탈로그. 모든 페이지를 링크·한 줄 요약과 함께 카테고리별로 정리. 인제스트마다 갱신. 질의 시 index를 먼저 읽고 관련 페이지로 파고든다. 소스 ~100개, 페이지 수백 개 규모까지 임베딩 없이도 잘 작동한다.
- **log.md** — 시간순 append-only 기록(인제스트·질의·린트). 일관 접두어(`## [2026-04-02] ingest | 제목`)를 쓰면 `grep`으로 파싱 가능하다.

## 선택: CLI 도구

규모가 커지면 위키 전용 검색 엔진이 유용하다. [qmd](https://github.com/tobi/qmd) 같은 로컬 마크다운 검색(BM25/벡터 하이브리드 + LLM 재랭킹, CLI + MCP)이 좋은 선택이다.

## 팁

- **Obsidian Web Clipper**로 웹 기사를 마크다운으로 수집.
- **Obsidian 그래프 뷰**로 위키의 형태(허브·고립 페이지) 파악.
- **Marp**로 위키 콘텐츠에서 슬라이드 생성.
- 위키는 결국 **마크다운 git 저장소** — 버전 관리·브랜치·협업이 공짜.
